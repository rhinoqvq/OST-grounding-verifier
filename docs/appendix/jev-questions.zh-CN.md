# 附录：Jev 题目清单（OP29）

[返回设计与实现](../design.zh-CN.md)

Jev 在这个系统里只做选择题和是非题。每次请求发一段材料（state）和一批互相独立的题，Jev 对每道题返回概率，代码再按阈值和组合规则做决定。这里按一次判定的流程，列出 OP29 默认配置下会问到的每一类题。题号由代码起，代码靠题号把答案对回到具体的单元。

选项的完整措辞在源码里，这里只写每个选项的意思。阈值见[设计与实现](../design.zh-CN.md#jev-怎么用)。

## 1. 拆回答（材料：只有回答）

代码在 [`semantics/propose_jev.py`](../../src/verifier/methods/optimized/semantics/propose_jev.py)。拆分时只给回答、不给原文，这样拆分不会被原文带偏。

| 题号 | 题型 | 问什么 | 选项 | 代码怎么用 |
|---|---|---|---|---|
| `cut::<句>::<位置>` | 选择 | 这个连接词处的切点属于哪一类 | 两件独立的事 / 因果 / 转折 / 先后 / 整句保留 / 不是边界；and 并列时，另给几个把共享开头补全的写法 | 最高选项到 0.60 才切；因果、先后另建关系节点 |
| `recomb::<切点题号>` | 是非 | 共享开头补全以后，两条合起来是不是还等于原句 | 是 / 否 | 不够把握就撤销这次切分 |
| `nc::<句>` | 选择 | 这句是在陈述可以核对的东西，还是纯粹对读者说的话（客套、过渡、「以下是步骤」） | 事实性陈述 / 元话语 | 元话语到 0.80 才排除，不进核对 |

## 2. 拆原文（只在原文超过约 2.6 万 token 时）

代码在 [`semantics/source_tree.py`](../../src/verifier/methods/optimized/semantics/source_tree.py)。材料是原文的一段（长段落分窗）。题目、选项、阈值和拆回答完全相同，只是措辞改成「原文句子」，题号前面加上段号和窗号，免得和回答侧混在一起。

## 3. 先按句判定（材料：整份原文，超过约 2.6 万 token 时收窄）

代码在 [`judge/sentence_call.py`](../../src/verifier/methods/optimized/judge/sentence_call.py) 和 [`judge/citation_probe.py`](../../src/verifier/methods/optimized/judge/citation_probe.py)。

| 题号 | 题型 | 问什么 | 选项 | 代码怎么用 |
|---|---|---|---|---|
| `v<k>` | 选择 | 回答的第 k 句，对照原文 | 原文说了 / 原文说的相反 / 原文既没说也没反驳 | 最高选项 |
| `e<k>` | 选择 | 哪一句原文是证据（说了它，或说了它的反面） | 每句原文一个选项，加「没有」 | 和上一题一起：判 S 且有证据句，这句的 claim 都定为 S |
| `cite::<claim>` | 选择 | 这条 claim 是哪一句原文说的 | 整句的证据句，加词面最接近的两句 | 到 0.50 就引这一句，否则沿用整句的证据句 |

这一步的三条定义用的是转述过的说法（「the passages state it」）。消融实验里，同样的转述放在整段一次判定上，比题目原文的定义更松，见[消融实验](../ablation.zh-CN.md#整段--按句判这一步拆开看)。

## 4. 逐条判定其余的 claim（材料：整份原文，超过约 2.6 万 token 时收窄）

代码在 [`judge/entail.py`](../../src/verifier/methods/optimized/judge/entail.py) 和 [`judge/treemap.py`](../../src/verifier/methods/optimized/judge/treemap.py)。

**判定和证据**

| 题号 | 题型 | 问什么 | 选项 | 代码怎么用 |
|---|---|---|---|---|
| `m::<claim>::<原文节点>` | 选择 | 只在建了原文树时：这个原文节点对这条 claim | 支持 / 矛盾 / 没提到 | 映射上了就判 S 并引这个节点，映射不上的走下面的整份原文判定 |
| `v::<claim>` | 选择 | 严格对照原文，不用外部知识，判这条 claim | 支持 / 矛盾 / 原文没有 | 最高选项低于 0.55 记 U，倾向 S 的除外 |
| `r::<claim>::<句>` | 是非 | 一个仔细的核查员会不会引这句当证据（只是话题相同不算） | 是 / 否 | 到 0.60 算相关证据；一句都不过时，保留排名第一、到 0.30 的那句 |
| `g::<claim>::<部件>` | 是非 | 整句保留的单元：这块内容原文里有没有（包括在条件、选项、转述里） | 是 / 否 | 出处门：有一块没出处，就把 S 降成 U |
| `c1::<claim>` | 选择 | 被引的原文句是不是明确排除了这条 claim | 排除 / 说的是别的东西 / 其实一致 | 只有「排除」才保留 C，否则降成 U |

**关系分步核对**（因果、先后、条件）

| 题号 | 题型 | 问什么 | 选项 | 代码怎么用 |
|---|---|---|---|---|
| `rel1::<claim>` | 选择 | 哪一句原文自己说了这种连接（不是只提到两边） | 每句原文一个选项，加「没有」 | 找不到 → U |
| `rel2` / `rel3::<claim>` | 选择 | 关系的这一边，和原文那句的对应一边 | 相同（或是它的实例）/ 相反 / 不同的东西 | 有一边相反 → C；有一边不同 → U；都相同才可能 S |
| `rel4::<claim>` | 选择 | 只问先后：原文说哪边先发生 | 和 claim 一致 / 相反 / 没说 | 相反 → C |
| `rel5::<claim>` | 是非 | 这句是不是用自己的口吻断言这个连接（不在条件、转述、问句、否定里） | 是 / 否 | 否 → 不能判 S |
| `rel6::<claim>` | 选择 | 条件句的条件，是不是有另一句原文说它成立 | 那一句 / 没有 | 必要条件（only if）不能这样推 |
| `rel7::<claim>` | 选择 | 两边的词对得上，是不是要靠另一句（别名、定义、等同） | 那一句 / 不需要 | 把这句加进引文 |

转折（but）不走这一组：它不额外断言什么机制，按两边成员汇总。

**两跳桥接**（普通判定拿不准时）

| 题号 | 题型 | 问什么 | 选项 |
|---|---|---|---|
| `br1::<claim>` | 选择 | 哪句原文把 claim 的主语连到了另一个实体（路由、别名、从属） | 那一句 / 没有 |
| `br2::<claim>` | 是非 | 这个连接是不是完整的（全部走过去、纯别名），「部分」「大约一半」都不算 | 是 / 否 |
| `br3::<claim>` | 选择 | 哪句原文说了 claim 断言的属性（任何极性，主语可以不同） | 那一句 / 没有 |
| `br4::<claim>` | 选择 | 只比属性本身，不管主语 | 相同 / 相反 / 不同 |
| `br5::<claim>` | 是非 | 属性那句说的，是不是桥接句连到的那个实体 | 是 / 否 |

都成立 → S，引两句；属性相反 → C。每一道都是单跳题，推理链由代码拼起来，不让 Jev 一道题做完整条推理。

## 5. 默认不走的题

- `fid::`、`cov::`：只在用生成式模型拆分时（`proposer=llm`）才问，检查拆分是否忠实、有没有漏掉内容。默认用代码切点加 Jev 分类，切出来的片段就是回答原文，不需要这一步。
- 父节点复核：一句里的事实全判 S 时把整句再判一次。OP29 默认关闭。
